# ADR 0005：插件体系——声明式数据包，零代码执行

状态：已接受 · 日期：2026-09-21

## 背景

社区生态需要扩展点（皮肤、桌宠形象、外部词典），而 InputFlow 的核心承诺是
「隐私优先、零遥测、权限全在自己手里」。常见 IME 的插件体系（可执行代码、
脚本引擎、在线市场自动更新）与这个承诺冲突：一个包就能带走所有击键。

## 决策

1. **插件只有一种形态：声明式数据包**。目录 + `plugin.json` 清单 + 数据文件
   （颜色表 / PNG / IFD1 词典）。没有任何可执行代码、脚本或宏——这不是 v1 的
   妥协，是长期边界。
2. **权限白名单制**。清单声明权限，内核只认识白名单里的权限
   （当前仅 `read:plain-text-dict`，供词典包读明文词库）；声明未知权限 =
   拒绝加载。皮肤/桌宠包无需任何权限。
3. **校验在内核**（`crates/plugin`，纯逻辑可单测）：id/版本/kind/入口文件/
   路径逃逸/权限全部过检；坏包跳过并给出用户可读原因，绝不中断整个目录。
4. **渲染在前端**。候选窗读 `theme.json`，桌宠读 `pet.json` + PNG，
   词典包走既有 `inputflow_new_with_dict`。内核崩溃面不因装包而扩大。
5. **安装 = 放目录**。`~/Library/Application Support/InputFlow/plugins/<id>/`，
   没有在线市场、没有自动更新、没有签名链。包从哪来、信不信，由用户决定。
6. **AI 化用开源工具**走 xtask 脚手架（`xtask plugin new/check`）：
   把任何开源配色方案/形象素材转成合规包的是工具和人，不是运行时代码。

## 化用开源配色

社区配色（如鼠须管的众多方案）是社区公有传统，例子包 `skin-moonlight`
注明了化用来源；包的 `license` 字段必填，让作者自己声明继承关系。

## 后果

- 好处：攻击面为零（数据不能执行）、离线可用、审计=看 JSON、生态门槛极低。
- 代价：无法做「代码级」功能插件（自定义按键处理等）。这类需求走两条正路：
  a) 长成内核 PR（公开可审计）；b) 未来评估「声明式规则」扩展（仍是数据）。
- 桌宠特效（打字跟随/鼠标追踪/礼花）由前端内置实现，包只用布尔值开关，
  不提供自定义代码钩子。
