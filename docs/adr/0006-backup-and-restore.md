# ADR-0006：数据备份与恢复

状态：已接受（M1）

## 背景

ADR-0005 把用户词、二元组、短语加密存进 `userdata.enc`，密钥在系统钥匙串。
这保证了本机安全，但也意味着**这个文件搬不走**：换机器、重装系统、密钥丢失，
学了半年的词库就没了。HeliBoard 的经验是备份/恢复属于离线键盘的刚需功能。

同时，用户词库本身就是一份「输入过什么」的画像，明文导出必须是显式、有警告的操作。

## 决策

### 两层格式

1. **内核信封**（`crates/core/src/backup.rs`，跨平台）：纯文本，
   `#IFBAK1` + `#kind` + `#items` + `#crc32` + TSV 正文。
   - 文本而非二进制：用户能自己打开看、能用任何工具检查；
   - CRC32 校验：截断或被改过的包一律拒绝，**不做部分导入**；
   - 正文就是 `UserModel::export_tsv()`，词 / `@pair` / `@phrase` 三种行，
     以后加行类型不破坏旧包（解析器按行前缀分派，认不出的行跳过）。

2. **平台加密包**（`platforms/macos/Sources/BackupManager.swift`，`.ifbak`）：
   `IFBK` + 版本 + 盐(16B) + ChaChaPoly(信封文本)，密钥由**用户密码**经
   PBKDF2-HMAC-SHA256（200k 次）派生，文件头作为 AAD。

关键取舍：**备份不复用钥匙串密钥**。用本机密钥加密的包换台机器就打不开，
那不叫备份。密码由用户设、不落盘，忘了就恢复不了——这点在导出对话框里明说。

### 导入语义

- **合并**（默认）：同名条目取次数较大的一方，重复导入同一份包不会让计数翻倍；
- **覆盖**：以备份为准替换同名条目；
- 校验失败时**不改动任何现有数据**（先解包验签，再动模型）。

### 边界

- 备份**不含剪切板历史**。剪切板里是密码、验证码、私聊，敏感度和用户词不是一个量级，
  默认不进备份；需要时用户可在剪切板窗口里自己复制。
- 明文导出走独立菜单项，弹警告二次确认，文件权限 0600。
- 备份是本地文件操作，不联网、不上传，任何形态的「云备份」都违反 ADR-0002。

## 影响

- 内核新增 `Session::export_backup` / `import_backup`，FFI 新增两个函数，各平台前端复用；
- `EncryptedStore.mergeUserModel` 改为行类型无关的合并（否则短语行会在合并时被丢掉）；
- 自检：`InputFlow --backup-smoke`（导出 → 加密 → 解密 → 导回 → 拒绝坏包）。
